# 双人成鼠 · Double Trouble, Tiny World

第三人称剧情 / 射击试玩。玩家始终操作小梅，科迪由 AI 控制：他会跟随、协助射击，也会打着“帮忙”的旗号给小梅制造麻烦。基于 Three.js + Android WebView，可离线运行。当前源码版本为 **0.3.1，序章「生日礼物」＋第一章「好心的捷径」＋第二章「十万块的地铁票」**。

## 序章「生日礼物」

- 木屋外景镜头 → 小梅、科迪登场 → 生日对白立绘。科迪每句有独立中文合成男声，点击「继续」立即打断当前音频并播放下一句。第一章科迪对白也已录成离线片段；不使用原演员声线。
- 门外两只丧尸拍门，门被撞开；获得 M92，共 60 发（15＋45）。教学依次要求移动、开火、完成换弹；完成前不会受伤。
- 敌人逐渐增多，最多同时 16 只，整场总计 60 只，门外两只计入总数。每只丧尸仍保留生成时抽定的待机 / 移动动作。
- 在场达到 10 只时，科迪只提出一次回礼选择。拒绝后不追加对白，继续战斗；接受后获得柯尔特 723，共 300 发（30＋270），自动装备。
- 科迪使用 M92 协助射击，命中概率 35%，单发身体伤害为玩家同武器的 70%。射偏会显示偏离的曳光线，不扣敌人血量。
- 击退第 60 只后播放结尾两句，显示保存 / 进入下一章 / 返回主菜单。完成状态可读档，选择下一章才进入原仓库关卡。

序章外景和战斗内景均使用提供的 `log_cabin.glb`，按宽 18 m 统一缩放；进入室内时剖去模型上层，保留原模型的圆木墙、地面、窗户、纹理和入口。碰撞从真实建筑网格提取；原入口门的木板和金属部件可被撞开，丧尸经门洞进入。旧存档中落在新墙体外的位置会迁至可走区域。

## 第一章内容

1. 主菜单：开始游戏、读取存档；已有存档时，新游戏有覆盖提示。
2. 小梅和科迪对话后，前往仓库配电台。
3. 科迪“开捷径”触发警报，玩家需要清理丧尸。
4. 取回电池后，科迪“省电”拔掉照明，引来第二批敌人。
5. 清理敌人、为出口供电，进入鼠洞完成第一章。

科迪会保持同行、绕过障碍并协助射击；他的恶作剧与关卡阶段绑定，恢复存档不会重复触发。剧情使用中文文字、角色立绘、对话动作和科迪逐句合成语音。

## 操作

- 左摇杆移动；右侧拖动视角。
- 瞄准按钮切换瞄准；按住开火连续射击。身体 / 头部命中伤害不同。
- 换弹，拾取蓝色弹药补给与红色医疗补给；敌人靠近后攻击小梅。
- 靠近目标后点击互动按钮；对白点击「继续」。
- 暂停菜单可保存、继续或保存并返回主菜单。流程检查点和游戏中间隔自动保存。被击倒后可读取存档。
- 桌面：WASD / 方向键移动，Q 瞄准，空格开火，R 换弹，1 / 2 切换武器，E 互动，Shift 疾跑，Esc 暂停，Enter 继续对白。

## 人物与动作

- 小梅与科迪：保留原模型、贴图、骨骼和蒙皮；包含 Idle、Run、RifleIdle、RifleRun、PistolAim、Aim、Talk。Idle 和 PistolAim 使用本次提供的 FBX。瞄准和对话来自用户提供的 FBX；移动瞄准采用上下半身分开播放。
- 丧尸：接入两种不同外形（原有血肉丧尸、补上骨骼的衬衫丧尸）。待机使用两份 Zombie Idle FBX；移动以提供的 `Running(2).fbx` 重定向下半身，配合 Zombie Idle 上半身，并调整为较短步幅和丧尸移动速度。两个移动选项共享相同烘焙姿势，以不同时长播放。模型、待机、移动和步速在生成时抽定，存档保留；重复上传的同一模型不作为第三种外形。
- 待机池：`Idle_Sway`、`Idle_Lurch`，分别由两份不同的 Zombie Idle FBX 适配。
- 移动池：`Walk_Shuffle` 使用提供的 Running(2) 下半身动作并适配丧尸步幅；`Walk_Heavy` 共享已烘焙姿势、时长为 1.22 倍，不来自第二份步行动作。
- **每个丧尸生成时，只抽取一次外形模型、待机动作、移动动作与步速。随后切换行为只使用这个个体已选中的动作；保存和读取均保留选择。**
- 统一显示身高，播放时约束脚底高度、消除移动动作的平面根位移。M92 和 723 使用本次提供的实际枪械模型；723 的外观来源为提供的 CAR-15 GLB。上传的 Pistol Idle 用于持枪低姿待机（PistolReady）；实际抬枪瞄准复用已适配的 Aim 上半身，避免把低姿待机误当成瞄准。步枪使用 Aim，移动瞄准分层混合。

## 存档

使用当前应用本地存储 `double-mice.save.v1`，数据结构升级为 version 3，并兼容原 version 1/2 存档。序章阶段、60 只计数、教程状态、接受 / 拒绝决定、各武器独立弹药均会保存。保存章节阶段、小梅位置 / 生命 / 弹药、科迪位置、已发生剧情、补给领取状态、存活丧尸的位置 / 生命 / 模型与动作选择及随机种子。无效或损坏的存档会提示重新开始，不会阻止菜单进入。

## 开发与验证

```bash
python3 -m http.server 8080 --directory web
npm install
npx playwright install chromium
npm test
npm run test:textures
npm run test:browser
npm run test:prologue
```

可设置 `LUNA_CHROMIUM` 指向已安装的 Chromium。浏览器测试使用 **从 Android MainActivity 直接读取的同一 CSP**，覆盖贴图、菜单、玩家移动、瞄准命中、弹药装填、剧情阶段、丧尸动作选择存档恢复、出口条件和死亡读档。测试截图默认输出到被忽略的 `build/qa`，可用 `LUNA_TEST_OUTPUT` 改变路径。

`models/base` 保存动画加工的基础模型，`models/animations` 保存本次实际使用的 FBX。Blender 4.x 中运行 `scripts/prepare_story_animations.py` 可重新生成 `web/assets` 的故事模型；`story-animation-report.json` 记录来源和帧数。原先的 `retarget.py`、`fix_grounding.py` 保留为早期移动测试的加工记录。

## 新资源与加工

`web/assets` 中枪械和木屋保持原几何，将内嵌纹理限制到 1024，并保留透明图；尺寸及输入哈希见 `environment-assets-report.json`。`scripts/prepare_environment.py <上传目录>` 可复现压缩。`scripts/prepare_prologue_animations.py` 在故事模型上重定向新动作；基础动作重建后再运行此脚本。

网络音效使用 CC0 来源，经静音裁切、峰值归一化、短淡入淡出、单声道 MP3 切片；来源、具体对象映射和切片时间见 `audio-sources/SOURCES.md`、`audio-slices.csv`。运行时不联网下载。新增音效覆盖枪械、换弹、脚步、木 / 金属 / 玻璃命中、丧尸、木门、补给、配电台、UI 与存档。

## Android 外壳

包名 `com.luna.movement`，显示名「双人成鼠」，源码版本 `0.3.1` / code 4。最低 Android 8 / API 26，目标 API 35；横屏，要求 OpenGL ES 3 和可用的 Android System WebView。没有 native `.so`，不依赖 32 位 CPU 运行库；全部资源随包提供，不请求网络权限。

后续需要打包时，使用 JDK 17、Android Platform 35 / Build Tools 35.0.1，运行 `scripts/build_apk.sh`。可通过 `LUNA_SDK`、`LUNA_BUILD_TOOLS`、`LUNA_JAVAC` 和 `LUNA_KEY` 指定工具及仓库外的开发签名证书。**本次只修改和验证源码，没有生成新 APK。**

所有用户提供的人物和动作资源的权利仍归各自权利人。本工程不替这些资源授予新许可。Three.js 按随附 MIT 许可使用。设备端限制见 `VALIDATION.md`。

## 模型修正（0.3.1）

修正枪械前向、握把枢轴和枪口坐标；小梅和科迪按各自手掌比例适配枪械，用双骨骼手臂 IK 与手腕 / 手指约束完成握持。移动瞄准保留瞄准姿势的骨盆旋转，降低跑步抬腿幅度。丧尸修正导出动作的骨盆、颈部基准，并按修正后的姿态统一尺寸。接地使用蒙皮鞋底采样点，动作以 140 ms 淡入淡出切换。

这些是游戏运行时的骨骼与挂点修正；原始上传模型的拓扑、纹理和蒙皮权重保持原样。`tests/model-rig.test.mjs` 会直接加载实际 GLB 的几何、骨骼和动作检查回归。

## 最新源码修正（尚未打包）

科迪的头部、眼睛、毛衣等 8 个材质从错误的透明混合模式改回不透明，避免部件排序造成空洞和透视。重新生成角色立绘。人物原网格、UV 和贴图数据保持；科迪 / 小梅 GLB 仍在 20–30 MB 内。

`scripts/fix_cody_materials.py` 修复科迪材质。`scripts/prepare_zombie_variants.py` 在 Blender 4.0.2 中从仓库保留的原模型和 FBX 重建丧尸；`gltf_animation_variants.py` 对已烘焙移动四元数做循环平滑，并从同一姿势生成较慢时序。新版丧尸带 `zombieRigVersion: 2` 标记，跳过旧版运行时骨盆 / 头部强行扶正。

`tests/assets-scene-smoke.cjs` 验证真实木屋内外景、两种丧尸同时生成、穿门进入和模型选择读档；`tests/cabin.test.mjs` 检查门洞和建筑碰撞。完整验证见 VALIDATION.md。

## 第二章：十万块的地铁票（源码，未打包）

第一章结尾选择「进入第二章」。使用上传的废弃地铁站，按真实隔墙、柱子与楼梯建立碰撞，活动范围为同一站台；上传模型没有列车，另外补充了简易车厢和绿色登车标记。

- 男市民包按骨架拆成 **11** 人，女市民包拆成 **6** 人，另有持 M92 的保安。48 个实体从模型池生成（含 6 名保安），外观与动作选择随存档固定。每个文件只包含一人的完整身体、衣物和骨架。
- 新待机来自 `Standing Idle.fbx`，行走来自 `Dwarf Walk.fbx`，恐慌跑步来自主角同源的 `running.fbx`。市民不会攻击小梅；受附近枪声惊吓后跑动，保安使用主角同款持枪、瞄准和移动逻辑；科迪只协助攻击保安。
- 对话结束后开始 **300 秒**倒计时；暂停、剧情对话不耗时。击毙实体掉落上传的金钱模型，每人 **¥1,000–5,000**，靠近自动拾取。全场至少 ¥120,000，实体不会无限重生。
- 靠近科迪互动偿还 **¥100,000**，随后在绿色登车点互动。未还清不能登车，超时失败，可重新挑战第二章。新章入口一次提供 M92 150 发备用弹；若已有步枪，补充 300 发备用弹。
- 科迪六句对白均有离线普通话男声切片，点击继续立即停止当前句。沿用通用合成音色，不模仿原演员。
- 两位主角新增程序步枪换弹：右手稳枪、左手取换弹匣，配合 Colt 的 2.05 秒装填计时；这不是上传 FBX 动作。附带弹匣仅在换弹中段可见。
- 存档结构 version 3，兼容 version 1/2；记录计时、还款、现金、存活实体和未拾取掉落物。死亡记录与已拾取 ID 去重，读档不会重新发钱或重置计时。

资源再生成：Blender 4 执行 `scripts/prepare_metro_assets.py -- /path/to/upload`，自动以 512 像素压缩各 NPC 贴图。站台和金钱使用该压缩脚本处理原上传 GLB，保留几何和 UV。站台随后使用 gltfpack 0.20 的 `-kn -km -ke -vp 16 -vt 16` 优化至约 26 MB，不删减三角面；使用 Three.js 原生支持的 KHR_mesh_quantization，无额外解码器。来源与每个拆分模型见 `metro-assets-report.json`。

验证：`npm test`、`node tests/metro-smoke.cjs`（设置 `LUNA_CHROMIUM`）。浏览器覆盖真实模型载入、17 个市民外观、保安装备、恐慌动作、实体碰撞、掉钱/拾取/读档去重、还款、登车、超时及双主角换弹。未进行 Android 真机性能测试，本次不生成 APK。
